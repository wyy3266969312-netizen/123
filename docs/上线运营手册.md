# 上线运营手册

这份文档写给工具的**卖家**（也就是你），不是给买家看的。
买家怎么用工具，看 [使用手册](使用手册.md)。

定价模式：**¥49 一次付清，永久使用**，没有月费和续费。

---

## 一、上线前要做的事

### 1. 生成两个密钥

```bash
openssl rand -base64 48
```

跑两次，得到两串随机字符串：

- 第一串给 `LICENSE_SIGNING_SECRET`（用来签发和校验卡密）
- 第二串给 `LICENSE_ADMIN_TOKEN`（用来保护发卡接口）

**把 `LICENSE_SIGNING_SECRET` 备份好。** 它一旦改动，**之前卖出去的所有卡密全部失效**。
两串都不要提交到仓库、不要发在聊天里。

### 2. 在 Vercel 配置环境变量

打开 Vercel 项目 → Settings → Environment Variables，加上：

| 变量名                      | 值                     | 必填       |
| --------------------------- | ---------------------- | ---------- |
| `LICENSE_SIGNING_SECRET`    | 上一步的第一串         | 是         |
| `LICENSE_ADMIN_TOKEN`       | 上一步的第二串         | 是         |
| `VITE_SUPABASE_URL`         | Supabase 项目 URL      | 账号版需要 |
| `VITE_SUPABASE_ANON_KEY`    | publishable key        | 账号版需要 |
| `SUPABASE_SERVICE_ROLE_KEY` | secret key（**绝密**） | 账号版需要 |
| `VITE_LICENSE_PRICE_LABEL`  | `¥49`                  | 否         |
| `VITE_LICENSE_CONTACT`      | 换微信号才需要         | 否         |
| `VITE_LICENSE_PAY_QR`       | 贴收款码才需要         | 否         |
| `LICENSE_REVOKED_SERIALS`   | 先留空                 | 否         |
| `DEEPSEEK_API_KEY`          | 想用 AI 回复翻译才需要 | 否         |

`VITE_` 开头的变量是**打包时**读进去的，改完必须重新部署才生效；
其他变量是服务端运行时读的，改完重新部署也能立刻生效。

### 3. 收款方式：先加微信，不放收款码

当前采用的是**微信优先**流程，付款页上不显示收款码：

1. 买家在付款页看到你的微信号 `el_hazel`，加你并备注「SOP 工具」
2. 你在微信里把收款方式发给他
3. 他转账 ¥49
4. 你发卡密给他（见第二节）

这样做的好处是每一单你都跟买家说上话，知道对方是谁、做什么品类，
以后要停用某张卡密时也对得上人。代价是多一步人工，量大了会累。

微信号写在代码默认值里（`src/licenseSalesInfo.ts`），不用配环境变量。
要换号就改 `VITE_LICENSE_CONTACT`，或者直接改那个默认值。

**以后想改成贴收款码自助付款**：把图片存成 `public/pay-qr.png`，
再配 `VITE_LICENSE_PAY_QR=/pay-qr.png`，付款页会自动显示它。
届时 `LicenseGate.tsx` 里那段「先加微信」的文案也要跟着改。

### 4. 部署后自查

- 打开首页 → 应该看到付款页，而不是工具本身。
- 打开 `https://你的域名/?demo=1` → 应该直接进入演示模式，不需要卡密。
  这是给潜在买家试用的免费入口，可以放心往外发。
- 给自己发一张卡密（见下一节），输入后应该解锁，刷新页面仍然是解锁状态。

## 一点五、账号版：开通一个新用户

现在有**两种**让人用上工具的方式，卡密和账号，两种都有效。新买家走账号，
老买家的卡密继续能用，不用管。

### 新买家的流程

1. 买家在付款页点「注册」，填邮箱和密码
2. 他会看到「账号已创建，等待开通」，页面上写着让他加你微信并报上注册邮箱
3. 他加你微信、付款 ¥49
4. **你去开通**（下一节）
5. 他点页面上的「我已付款，刷新看看」，立刻就能用了

### 怎么开通

打开 Supabase → 左侧 **Table Editor** → 选 **profiles** 表。

每个注册的人是一行。找到他的邮箱那一行：

- 把 **approved** 那一格改成 **true**（打勾）
- **note** 那一格记一下付款渠道和金额，比如「微信 2026-09-08 ¥49」

改完自动保存。**停用某个人就是把 approved 改回 false。**

比卡密强在：你能看见每个人是谁、什么时候注册的；停用针对具体某个人，
不用再自己维护「卡密对应谁」的表格。

### ⚠️ 注册的人不可能自己给自己开通

`profiles` 表开了行级安全，策略只给「读自己那行」的权限，**没有任何写权限**。
只有你在 Supabase 后台、以及服务端用 secret key 时才改得动 `approved`。
这一条是整套模式成立的前提，已经实测验证过。

## 一点七、发信：忘记密码要用到的邮件配置

买家点「忘记密码？」时，Supabase 会发一封带重置链接的邮件。这套配置只做一次，
但每一环少一样都不发信，而且**失败是静默的** —— 接口照样返回成功，信就是不到。
所以下面每一步都值得对着核一遍。

### 1. 为什么不能用 Supabase 自带的邮件服务

它每小时只发 2 封，而且**只投递给项目成员自己的邮箱**。你自己测的时候能收到，
买家永远收不到 —— 这是最容易误判成「已经能用了」的一个坑。必须接自己的 SMTP。

选的是**阿里云邮件推送**，不是 Resend 之类的国外服务：域名解析本来就在阿里云，
省一半事；更重要的是投递率，买家大多用 QQ 邮箱和 163，国外服务发过去经常进
垃圾箱甚至被丢弃。实测阿里云发到 QQ 邮箱是直接进收件箱的。

### 2. 阿里云邮件推送（dm.console.aliyun.com）

**发信域名**用子域 `mail.hazelcreators.com`，不要用主域 —— 主域将来自己要收信时
不会打架。

建好之后按控制台给出的清单在云解析里加四条记录。主机记录**只填前缀**，
阿里云会自动补后面那截；填成完整域名会变成 `mail.hazelcreators.com.hazelcreators.com`，
验证永远过不了。

| 类型 | 主机记录                             | 说明                                              |
| ---- | ------------------------------------ | ------------------------------------------------- |
| TXT  | `aliyun-cn-hangzhou._domainkey.mail` | DKIM，值有 200 多字符，复制时容易被页面省略号截断 |
| TXT  | `mail`                               | SPF                                               |
| TXT  | `_dmarc.mail`                        | DMARC                                             |
| MX   | `mail`                               | 优先级填 10，四条里唯一要填优先级的               |

**发信地址**：账号名 `noreply`，发信类型选**触发邮件**（不是批量邮件），
回信地址填一个自己能收的邮箱并去点验证链接 —— 不验证的话系统会随机分配一个
回信地址，买家回复的信你永远看不到。

建好后点「设置SMTP密码」，这个密码**设完就看不到了**，当场记下来。生效要等 2 分钟。

### 3. Supabase → Authentication → Emails → SMTP Settings

| 字段                 | 值                                                                 |
| -------------------- | ------------------------------------------------------------------ |
| Enable custom SMTP   | 打开                                                               |
| Sender email address | `noreply@mail.hazelcreators.com`                                   |
| Sender name          | `Hazel 达人营销`                                                   |
| Host                 | `smtpdm.aliyun.com`                                                |
| Port number          | `465`                                                              |
| Username             | `noreply@mail.hazelcreators.com`（阿里云的用户名就是完整发信地址） |
| Password             | 上一步那个 SMTP 密码                                               |

**填完一定要滚到页面底部点 Save changes，然后刷新页面确认值还在。**
这一页的灰色文字是占位符不是值 —— 只填不存的话，刷新后会全部变回灰色，
Supabase 悄悄退回自带服务，于是又回到第 1 条那个坑里。这个坑实际踩过一次。

### 4. Supabase → Authentication → URL Configuration

- Site URL：`https://hazelcreators.com`
- Redirect URLs 加一条：`https://hazelcreators.com/**`

用 `/**` 而不是精确地址，因为重置链接回来时带着 `?recovery=1`，glob 要能覆盖
查询串。**注意**：这个白名单填错不会报错 —— Supabase 会静默回退到 Site URL，
所以配没配对只能从收到的链接上看。

### 5. 邮件正文

默认模板是英文的。中英对照的版本存在 [邮件模板](邮件模板.md) 里，直接粘贴即可。

### 排查：说好了发信却没收到

按这个顺序查，能少走很多弯路：

1. **这个邮箱注册过吗** —— 去 Authentication → Users 确认。`recover` 接口对
   没注册过的邮箱一律返回成功但**不发信**（防止被拿去探测谁有账号）。测试时
   用了没注册的邮箱，配置对错都收不到信。这一条排查时最容易漏，实际上浪费过
   两轮。
2. **SMTP 真的存上了吗** —— 刷新那一页，看值是黑字还是灰字。
3. **Supabase → Logs → Auth Logs** —— SMTP 报错会写在这里。
4. **阿里云 → 数据统计 → 发送数据** —— 今天发送量是 0，说明阿里云根本没收到，
   问题在 Supabase 那一段；不是 0 就说明发了，是收件方拦的。

## 二、卖出一单之后：发卡密（老方式，仍然可用）

买家付款后，用下面这条命令生成一串卡密：

```bash
curl -X POST https://你的域名/api/issue-license \
  -H "x-admin-token: 你的_LICENSE_ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"count":1,"note":"微信 张三 2026-08-26"}'
```

返回长这样：

```json
{
  "keys": ["SOP-A2BC-D3EF-GH4J-KMN5-PQR6"],
  "note": "微信 张三 2026-08-26",
  "issuedAt": "2026-08-26T09:00:00.000Z"
}
```

把 `keys` 里那串发给买家就行。

关于 `note`：服务器**不保存任何东西**，`note` 只是原样回显，方便你把「卡密 ↔ 买家」
一起粘进自己的表格里。**请自己维护一份卖出记录**，否则以后要停用某张卡密时，
你会不知道该停哪一张。建议至少记：日期、买家、付款渠道、卡密。

一次最多能生成 50 张（`"count": 50`），适合提前备一批。

## 三、需要停用一张卡密时（退款、卡密被转发）

1. 从卡密里取出**序列号**：`SOP-` 后面的 8 位。
   例如 `SOP-A2BC-D3EF-GH4J-KMN5-PQR6` 的序列号是 `A2BCD3EF`。
2. 把它加进 Vercel 的 `LICENSE_REVOKED_SERIALS`，多个用逗号隔开。
3. 重新部署。

生效时间：新激活立刻被拒；已经解锁的浏览器**最多 14 天后**掉线——
工具每 14 天会回来复查一次卡密。

## 四、这套方案挡得住什么，挡不住什么

**挡得住的：**

- 没付钱的人打不开工具，只能看演示模式。
- 没付钱的人**调不动你花钱的 AI 接口**。翻译和拍摄要求两个接口在服务端也会验卡密，
  不带有效卡密的请求会被直接拒掉，不会产生任何 DeepSeek 费用。

**挡不住的，心里要有数：**

- **一张卡密可以被多人共用。** 系统不数设备台数（那需要数据库，这版没有）。
  一个人买了发到群里，群里的人都能用。发现了就按第三节停用那张卡密。
- **懂技术的人可以绕过前端的付费墙。** 网页应用的代码全在浏览器里，这是没法根治的。
  但绕过去只能拿到本地功能，花钱的 AI 接口仍然进不去。
- 只要卡密和签名密钥没泄露，伪造一张卡密在实际中做不到（要猜中 12 位签名，
  接口还带了限速）。

综合下来：¥49 这个价位、面向真实客户手动发货的场景，这套方案是够用的。
如果以后要做「一张卡密限 N 台设备」「自动收款自动发货」，那时候再接数据库和
支付 webhook，卡密格式不用变。

## 五、常见问题

**买家换电脑了怎么办？**
让他把同一张卡密再输一遍就行，不用重新买。卡密不绑定设备。
提醒他：达人数据存在原来那台电脑的浏览器里，要用工具里的导出功能带过去。

**买家清了浏览器数据，工具又要卡密了？**
同上，重新输入原来那张卡密。所以卖出的卡密要让买家自己存好。

**买家说输入卡密没反应 / 提示连不上服务器？**
先确认他打开的是正式域名，不是本地地址。再检查 Vercel 上
`LICENSE_SIGNING_SECRET` 是否还在——如果这个变量被删了，所有卡密都会校验失败，
页面会提示「服务端未配置 LICENSE_SIGNING_SECRET」。

**能不能先免费试用几天再收费？**
现在没有试用期机制。免费入口是演示模式（`?demo=1`），用的是假数据，
可以随便发给潜在买家。

**我自己开发的时候也要输卡密吗？**
不用。`npm run dev` 是开发模式，付费墙自动关闭。
但 `npm run preview` 是正式构建，会显示付款页而且没法验证卡密——
要测付费墙，请在真实部署或 Vercel 的 preview 部署上测。
